# Clase 02 — Sistemas y datos responsables

### 1️⃣ 📘 Identificación

- **Tema principal:** evaluación del curso y perspectiva de sistemas aplicada a la ingeniería de software.
- **Subtemas y actividades:** manifiesto de compromiso; ética y trabajo profesional; análisis de problemas; teoría general de sistemas; sistemas de información y organizaciones; datos, servicios digitales y privacidad; requisitos y metodologías de desarrollo.
- **Propósito:** relacionar el análisis de software con el contexto técnico, organizacional y humano en el que operará una solución.

### 2️⃣ 📝 Resumen explicativo

**Evaluación y acuerdos de trabajo.** El profesor explicó los componentes de evaluación de los parciales, la asistencia, la posibilidad de exentar el ordinario y el proyecto final. La transcripción menciona varios porcentajes, pero no deja suficientemente clara la relación entre todos ellos para reconstruir una fórmula única. También describió una dinámica de participación en clase y pidió entregar a tiempo los trabajos indicados.

El grupo redactó y firmó un manifiesto personal de compromiso. Incluía puntualidad, participación constructiva, mantener el equipo de cómputo en condiciones adecuadas, cumplir tareas y proyectos con calidad profesional, colaborar de manera equitativa y actuar con ética, autoría y veracidad. El profesor aclaró que el documento era un compromiso de cada estudiante consigo mismo, no una promesa dirigida al profesor.

**Criterio profesional y análisis.** Se destacó que el trabajo en software requiere comprender problemas, estimar esfuerzos, coordinar perfiles distintos y explicar decisiones a personas que no necesariamente usan el mismo lenguaje técnico. El profesor recomendó resolver fallas de manera metódica: revisar mensajes y registros, comprobar el contexto y ejecutar pruebas antes de cambiar código. La creatividad y la inteligencia artificial pueden apoyar el trabajo, pero el resultado se debe entender y validar; aceptar una respuesta sin comprenderla puede introducir errores nuevos.

**Sistemas y contexto.** La sesión presentó la idea de que un sistema puede estar compuesto por partes que interactúan y, a su vez, formar parte de sistemas mayores. En computación, el software se relaciona con datos, infraestructura y personas; las organizaciones dependen de esos sistemas para operar. Se usaron ejemplos de redes sociales, servicios en la nube, licencias y modelos de software como servicio para discutir el valor económico de la información y la importancia de conocer las condiciones de uso y las políticas de privacidad. Fueron ejemplos para contextualizar el tema, no una revisión técnica de cada plataforma.

**Ingeniería de software y requisitos.** Se introdujeron los ciclos de desarrollo y metodologías como cascada y Agile, junto con la documentación de procesos y el portafolio de evidencias. Para definir un sistema, primero se debe expresar la necesidad en lenguaje natural, preguntar quién usará la solución, para qué la necesita y qué resultado espera. Ese análisis permite precisar el propósito y convertir una solicitud ambigua —por ejemplo, “mandar un mensaje”— en requisitos que puedan evaluarse. El curso se orientaría al análisis y la documentación de una propuesta, sin desarrollar necesariamente el sistema completo en esta actividad.

### 3️⃣ 🧩 Conceptos teóricos y técnicos relevantes

- **Sistema:** conjunto de elementos relacionados que interactúan y pueden formar parte de una estructura mayor.
- **Sistema de información:** componentes que capturan, procesan, almacenan o comunican información para apoyar actividades de una organización.
- **Requisito:** descripción de una necesidad o condición que la solución debe atender; debe precisarse con preguntas sobre propósito, usuarios y resultados esperados.
- **Ciclo de desarrollo:** etapas organizadas para analizar, construir, evaluar y mantener software; se mencionaron enfoques como cascada y Agile.
- **Estimación:** cálculo razonado del esfuerzo y tiempo que requiere una actividad, considerando alcance, dependencias y validación.
- **Depuración metódica:** comprobar el entorno, revisar mensajes o registros y probar hipótesis antes de modificar una solución.
- **Software como servicio (SaaS):** modalidad en la que se accede al software como servicio; la sesión la usó para hablar de modelos actuales de distribución.
- **Ética y privacidad:** responsabilidad de cuidar la autoría, la veracidad y el uso de información personal en los sistemas.

### 6️⃣ ✅ Síntesis final

Comprender el contexto antes de definir una solución.
Precisar las necesidades con preguntas sobre usuarios y propósito.

Los sistemas de información conectan tecnología, organizaciones y personas.
La ética incluye autoría, veracidad y cuidado de los datos.
