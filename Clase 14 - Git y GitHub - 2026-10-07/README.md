# Clase 14: Git y GitHub en trabajo colaborativo

### 1️⃣ 📘 Identificación

- **Asignatura:** Ingeniería de Software I
- **Clase:** 14
- **Fecha:** 7 de octubre de 2026
- **Tema:** Flujo de trabajo colaborativo con Git y GitHub: ramas, commits, pull requests, revisión y conflictos.
- **Fuente principal:** `Ing del Software 1- Clase 14.txt`.

### 2️⃣ 📝 Resumen explicativo

La sesión fue una práctica sobre un repositorio compartido. El grupo debía clonarlo, crear una rama propia, modificar un archivo Markdown común con la lista de integrantes por equipo, confirmar los cambios, subir la rama y abrir un pull request. El profesor revisó las propuestas y mostró cómo comentar, solicitar correcciones, atender comentarios y pedir una nueva revisión.

La actividad permitió observar que cambios aparentemente pequeños —como insertar saltos de línea o editar una versión desactualizada— pueden afectar el trabajo de quienes modifican el mismo archivo. Cuando aparecieron conflictos, el cambio no podía integrarse hasta que su autor los resolviera. El profesor recomendó sincronizar el repositorio antes de trabajar y mantener comunicación entre integrantes. También señaló que la participación individual se revisaría mediante la actividad registrada en GitHub.

Como siguiente actividad, los equipos debían proponer la estructura inicial de la documentación de su módulo y preparar una estrategia de organización para reducir los conflictos al integrar cambios.

### 3️⃣ 🧩 Conceptos teóricos y técnicos relevantes

- **Clonación:** obtener una copia local del repositorio para trabajar desde el equipo propio.
- **Rama:** espacio de trabajo separado para preparar cambios sin editar directamente la rama protegida del proyecto.
- **Commit y push:** registrar los cambios localmente y subir la rama al repositorio remoto.
- **Pull request (PR):** propuesta para revisar e integrar cambios; puede recibir comentarios y solicitar correcciones antes de aprobarse.
- **Conflicto de integración:** ocurre cuando cambios concurrentes no pueden combinarse automáticamente; requiere revisión y resolución.
- **Sincronización:** actualizar la copia local con los cambios recientes del repositorio antes de seguir trabajando.
- **Markdown:** el archivo de la actividad usó listas numeradas y viñetas; su sintaxis afecta la forma en que GitHub presenta el contenido.
- **Colaboración ágil:** la actividad ejercitó comunicación frecuente, trabajo en equipo y entregas incrementales.

### 4️⃣ ⚠️ Problemas, errores o aclaraciones del profesor

- No se debía editar directamente la rama compartida; cada participante tenía que trabajar en una rama propia.
- Algunos PR necesitaron correcciones de formato, comentarios atendidos o resolución de conflictos antes de poder integrarse.
- El profesor recomendó evitar cambios de formato innecesarios en un archivo compartido, porque pueden desplazar líneas y complicar la integración.
- Una persona hizo un *fork* del repositorio; el profesor explicó ese flujo, pero aclaró que para este ejercicio esperaba trabajar desde el repositorio clonado y con una rama propia.
- La transcripción alterna nombres de ramas y contiene errores de reconocimiento en términos como *pull request* y *merge*; por ello, el resumen describe el flujo sin atribuir un nombre inequívoco a la rama de integración.
- La estrategia para mitigar conflictos y la estructura final de los documentos de módulo quedaron como trabajo para la siguiente clase; no se presenta aquí una solución que aún no aparece en la sesión.

### 5️⃣ 🧠 Conclusión de la clase

La práctica mostró que Git y GitHub facilitan la colaboración, pero no eliminan los problemas de coordinación. Para integrar cambios con menos fricción, cada persona debe trabajar en una rama, sincronizarse, revisar comentarios y resolver conflictos; los equipos también necesitan acordar cómo se repartirán y documentarán sus tareas.

### 6️⃣ ✅ Síntesis final

El grupo practicó clonación, ramas, commits, push y pull requests.
La revisión incluyó comentarios, correcciones y nuevas solicitudes de revisión.
Los cambios simultáneos en un archivo generaron conflictos y retrasaron integraciones.
Se dejó como actividad proponer una estrategia de organización y mitigación.
